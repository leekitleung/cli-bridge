# 红线规则 (Red Lines)

红线是"一票否决"规则。存在任何红线意味着绝对不能发布。

## 安全红线

以下问题无论分数多高都禁止合并：

| 红线 | 说明 | 严重程度 |
|------|------|----------|
| R-01 | 任意代码执行漏洞 | P0 |
| R-02 | 未授权访问漏洞 | P0 |
| R-03 | 敏感数据明文泄露（日志/响应/存储） | P0 |
| R-04 | 权限绕过 | P0 |
| R-05 | 已知 CVE 漏洞 | P0 |
| R-06 | SQL/NoSQL/命令注入 | P0 |
| R-07 | XSS 存储型漏洞 | P0 |
| R-08 | API key/token 硬编码 | P0 |

## 功能红线

| 红线 | 说明 | 严重程度 |
|------|------|----------|
| R-10 | 主路径完全不可用 | P0 |
| R-11 | 核心功能报错无法使用 | P0 |
| R-12 | 用户无法完成任务闭环 | P0 |
| R-13 | 构建失败 | P0 |
| R-14 | 测试套件有未通过的测试 | P0 |

## 体验红线

| 红线 | 说明 | 严重程度 |
|------|------|----------|
| R-20 | README 完全缺失或无法运行 | P0 |
| R-21 | 安装后完全无法启动 | P0 |
| R-22 | 无任何使用说明 | P0 |
| R-23 | 主路径界面明显粗糙（UI 项目） | P1 |
| R-24 | 可点击元素不可辨认（UI 项目） | P1 |

## 架构红线

| 红线 | 说明 | 严重程度 |
|------|------|----------|
| R-30 | 循环依赖 | P0 |
| R-31 | 全局可变状态 | P1 |
| R-32 | 同步副作用在关键路径 | P1 |

## P0 vs P1

**P0**: 必须立即修复，否则绝对不能发布
**P1**: 强烈建议修复，可以有条件发布但需要明确说明风险

## 红线检查流程

1. 运行 `review-gate.mjs --check-redlines`
2. 如果发现红线，输出具体位置和修复建议
3. 不生成 final-report.md
4. 阻塞发布流程

## 常见红线误判

以下不是红线，但需要记录：
- 代码风格不一致（除非严重影呁可读性）
- 缺少某些测试（但核心路径有测试）
- 文档不完整（但有基本使用说明）
- 小幅性能问题（但不影响功能）
