# 评分标准 (Scoring Rubric)

## 总则

1. **每项 >= 90 分才能通过**
2. **存在任何红线则直接打回**
3. **评分应基于实际证据，不是猜测**

## 分数档位

| 档位 | 分数范围 | 含义 |
|------|----------|------|
| A | 90-100 | 优秀，无需改进即可发布 |
| B | 80-89 | 良好，有小问题建议改进 |
| C | 70-79 | 及格，有较多问题需修复 |
| D | 60-69 | 不及格，有严重问题 |
| F | <60 | 不可接受，需要重构 |

## 评分校准

### 高分标准 (90+)
- 完美或接近完美
- 有实际证据支持
- 无可改进空间
- 或有微小改进但不影呁使用

### 中等分数 (70-89)
- 功能正常但有改进空间
- 有 2-3 个小问题
- 不影响核心功能

### 低分标准 (<70)
- 有明显功能缺失
- 有影响使用的 bug
- 有安全隐患
- 架构有严重问题

## 评分一致性

为保证评分一致性：
1. 每项扣分必须有具体证据
2. 扣分时引用具体文件/代码
3. 分数变化应有理由说明
4. 同一问题不重复扣分
